# hall-of-heroes
## summary
Hall of heroes is a webapp meant to record the results of my board games sessions with friends. Because my friends and I use it, I intend it to be a mobile first app, one that we can easily pull out at board game sessions to record the results of sessions. This builds off a long-standing tradition we have of the victor writing the a quote of their choosing so we can remember fun sessions. The webapp is meant to have an old, tavern style aesthetic though I'm open to iterating that. 
## known specs
- I want a fun landing page for mobile users to navigate, something very visually enticing like a bunch of floating quotes to click on
- The first major spec I want is for the app to have some basic level of security. I'm not entirely sure how that might look, but the ideas i've had are leveraging SSO with something like gmail or leveraging a simple passcode i can pass to friends and authenticate. This is just to prevent non-users from submitting data and altering the site
- the website should be composed of pages that are fetchable by ID. The main types of pages of this style are player pages, game pages, and game session pages. Player pages show stats specific to that player, game pages show stats specific to that type of board game, and session pages show that specific sessions results
- the website will need a workflow for inputting the results of a new session. Relevant information is the date, quote, players involved, scores, what game it was, and victor.  Some games are co-op, rendering some of these choices possibly moot
- another spec is that I want their to be fun analytics or statistics for the player and game pages, like a player's win rate. This should reflect some of the popular style game analytics pages like na.op.gg which documents how League of Legends players do, or lolchess for Teamfight tactics.
- I'll need a method to bring on existing data - we have a plethora of that. One thing is that the data to bring on will likely be incomplete in some ways, most notably i likely won't have all of the participants of pass games unfortunately. But the player, date, and victor should all be there. I'm unsure if i want an "import" page or if I just want to be able to update this in the backend
- I'll want the data for this site to persist in some meaningful ways - i have concerns if I forget to pay for a DB subscription for example. To that end, I envision some sync or pehaps a regular email system or something that persists the data in a redundant way
- I'm also unsure if i want to allow for users to add new players/boardgames, as I want fun graphics, icons, animations, or general liveliness to each boardgame page or statistics, which may mean each needs to be added via code change. That's fine though given that new board games don't come super frequently
- I also want to add a game page, where there's a daily game puzzle for fun. One variation i imagine is a rotatin quote that is shown, and the user has to guess who said it, what game it was for, and when it was said, with points and a highscore chart.
## architecture rough draft
- the rough architecture i imagine is a webapp, likely react, some sort of backend service, say express, and some sort of database holder. I'm not sure if i really need something heavy like a true relational database, I'm imagining something lighter like mongoDB could work.
- the data structure relation is that there is a player table, a game table, and a session table. Player, game and session tables have info on their respective entities, like names, quotes, dates, etc. Then a mapping table should exist between session and player, as there can be variable amounts of players per session
- i'm not sure if i'll need additional tables to keep track of other things like statistics, or if they should be generated on the fly. I'll probably want some sort of table for the minigame portion of the website
- I'm not sure how to handle the architecture of authentication frankly, i'm not familiar
- I have cloudfront pages and intend to deploy there. I intend to deploy there with either a custom domain that i newly buy, or a subdomian of my existing personal website.
